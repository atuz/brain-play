# 小小动脑场 · Brain Play

轻巧、适合手机的多语言益智小游戏合集。原生 HTML / CSS / JavaScript，不需要服务器或账号；所有运行资源随站点提供。

## 游戏（15 款）

- 百战小旅鼠：八种技能、三个章节、24 个原创固定关卡，最大 1040×224 像素可施工场地。先选技能再点角色，支持暂停瞄准、单步、撤销、出兵速度、快进、拖动、小地图、全景、技能图鉴和逐关续玩。人物、施工和场景均为代码自绘。已通过真实手机尺寸网页控件逐关营救成功；[实现与验证](research/lemmings/IMPLEMENTATION.md) 区分原版研究、自制引擎测试和实际网页操作。
- 激光坦克：16 个原创固定关卡；反射镜、旋转镜、推箱搭桥、冰面、薄冰、传送门、敌炮与运送格。触屏/键盘移动与射击、撤销、图鉴、逐关续玩。
- 分子拼图：18 个原创固定关卡，从两原子分子到八原子分子和彩晶图案；元素、连接方向和键数都要匹配。触屏点选/滑动、目标模型拖动比对、撤销/重做、续玩。部分小关经完整搜索标注最少步数。
- 蘑菇花园：24 个原创固定关卡、19 类物品/地形，喂花、晶石、蛋、隐身、钥匙、激光和十字爆破；三章配色，最大 17×13 地图。默认思考模式，可选实时模式；物品说明、回合计数、撤销、暂停、全景与自动跟随、续玩。
- 机关工坊：受 The Incredible Machine 启发的原创机关游戏。37 个可直接选取的固定关卡（7 关练习、30 关正式挑战）、5 种场景与自由实验；41 种道具及连接工具，支持滑轮绕绳、真实支点跷跷板、蓄力弹射、定向照明、炮击和遥控爆破。点放／拖放、15° 旋转、翻转、单独归还、撤销、暂停、慢动作和轨迹。多目标必须全部完成；每个参考摆法通过实际物理运算验证。保存每关摆法、通关和自由实验；运行中返回恢复运行前的摆法。动物机关尚未加入。
- 蚂蚁多米诺：独立 JavaScript 规则引擎、原创矢量角色和 36 个固定关卡，按五章从 9×7 扩展到 25×25。沿平台与梯子自由搬动骨牌，一次推动触发连锁；普通、延时、搭桥、消失、分叉、开门六种牌，开门牌严格最后倒下后还需走进门。角色有独立迈步、爬梯、抱牌、放牌、伸手推动和进门动作，携带牌保持完整尺寸；动作支持撤销和关闭动画。大场地拖动、缩放、全景与镜头跟随，点按寻路、方向按钮、撤销、重试、逐步提示、图鉴和自动续玩，三种语言。允许多种解法。
- 2048／2584：3×3、4×4、5×5 棋盘，经典与斐波那契两种玩法；触屏滑动、键盘、方向按钮、撤销，各组合独立保存进度和最高分。经典 3×3 目标为 512，4×4／5×5 为 2048；斐波那契目标为 2584。
- 24 点：手机点选卡牌合并，逐张发牌和翻牌、双牌汇合动画、精确分数运算、撤销与原牌重来、当前局面的一步提示、过关反馈与本机记录。
- 水果连连看：最多两次转弯，支持棋盘外侧路径、提示、撤销、无可消组合自动整理；显示实际连接路径，提示同时高亮两个水果，整理保留空格位置。
- 消灭星星：点选一组预览得分，再点消除；真实下落及空列左移动画、剩余奖励、撤销。
- 熄灯：保证有解的随机棋盘、GF(2) 求解提示、撤销。
- 数字拼图：合法移动打乱保证有解；点按、滑动和箭头均按数字移动方向；真实滑动、目标小棋盘、撤销。
- 接水管：随机生成连通网络，旋转、漏口检测、提示及撤销。
- 迷你数织：原创 5×5 固定关卡，拖动涂色／标空、整笔撤销、线索完成反馈、下一关、每日挑战。
- 猜数字：四位互不重复数字，页面内数字键盘、选位修改、草稿恢复、A/B 翻牌反馈，不限次数。

普通浏览器的进度、音效选项和记录保存在 localStorage 中。支持存档接口的手机 App 内，每个游戏使用固定编码保存；操作期间只更新内存，返回游戏首页或返回 App 时才传一次完整存档，原生写入手机后再 pop。下次进入游戏自动恢复，不询问是否保存。突然关闭或崩溃时保留上次返回的存档。

## App 链接与语言

App 打开网站时，可把两位国家／地区代码放在 `country` 参数中，语言使用 `lang`：

```text
https://atuz.github.io/brain-play/?country=CA&lang=zh-CN#/
https://atuz.github.io/brain-play/?country=CA&lang=en#/game/twentyfour
```

- `country`：优先使用 App 链接中的有效代码，自动转成大写。没有时，从浏览器语言地区中读取，例如 `en-CA` → `CA`；浏览器未提供地区则留空。不会请求 IP 定位服务。
- `lang`：支持 `zh-CN`、`zh-TW`、`en`；顺序为链接参数 → 保存的语言 → 浏览器语言 → English。
- 参数放在 `#` 前。进入游戏、返回首页、切换语言都会保留国家码与其他查询参数；切换语言保留当前游戏进度。
- 首页设置仅提供语言、音效和动画。国家码不显示在设置中，仍按 App 链接或浏览器地区自动取得并保留在 URL 中。

## iOS WebView 返回

App 链接增加 `app=1`，例如 `https://atuz.github.io/brain-play/?app=1&country=US&lang=zh-CN#/`。
网页也会自动识别原生注入的 `window.webkit.messageHandlers.brainPlay`，不依赖 User-Agent 猜测。

- 首页左上角显示“返回 App”；游戏页面保留返回小游戏首页的箭头，右上角的 × 返回 App。
- 网页通过 `brainPlay.postMessage({type: 'close', source: 'brain-play', version: 1})` 请求原生 pop；不会用网页历史模拟退出 App。
- 页面就绪发送相同结构的 `type: 'ready'` 消息。原生在收到可信页面的 ready 后隐藏备用返回栏；加载失败时恢复备用栏。
- App 只接受本站 `/brain-play/` 主页面发来的消息，其他来源和子 frame 不处理。语言设置、游戏切换会保留 `app` 参数。
- `app=0` 可以显式关闭网页的 App 导航；普通浏览器不会出现“返回 App”。

## App 存档接口 v1

原生在主页面 `documentStart` 注入 `window.__brainPlayStorage = {version: 1, save: 存档或null}`，并提供上面的 `brainPlay` 消息接口。网页在首次渲染前同步恢复；`null` 表示第一次使用，可从旧 WebView 的 localStorage 迁移。已有原生存档优先于浏览器副本。旧 App 没有注入此接口时继续使用浏览器保存。

当前网页自定的存档格式：`{version: 1, games: {g001: {state: ...}}, settings: {...}}`。存档内容和迁移由网页管理，App 只保存、取回 JSON，不解析其中的游戏、字段或数据版本；可以使用对象、数组或 JSON 标量。通信外层的 `version: 1` 是接口版本，不限制 `save` 的内容。2026-10-22 起的原生实现取消了原有存档结构校验；已安装的旧 App 仍有旧限制，需更新后才能接收未来的新结构。现有文件路径保持不变。

编码固定，与显示语言和游戏名称无关，不回收重用：

| 编码 | 游戏 |
| --- | --- |
| g001 | 2048／2584 |
| g002 | 24 点 |
| g003 | 水果连连看 |
| g004 | 消灭星星 |
| g005 | 熄灯 |
| g006 | 数字拼图 |
| g007 | 接水管 |
| g008 | 迷你数织 |
| g009 | 猜数字 |
| g010 | 蚂蚁多米诺 |
| g011 | 机关工坊 |
| g012 | 激光坦克 |
| g013 | 分子拼图 |
| g014 | 蘑菇花园 |
| g015 | 百战小旅鼠 |

每个编码下保存 `state`、`best`、`completed` 等槽位；2048 的 `state:classic:3`／`state:fibonacci:5` 等六个组合独立保存，`state:daily:YYYYMMDD` 为每日局面。`settings` 仅包含语言地区、音效、动画。普通网页的其他 localStorage 数据不会传入 App。

- 返回游戏首页：`{type: 'save', source: 'brain-play', version: 1, save: 完整存档}`，不退出 App。
- 返回 App：同结构的 `type: 'close'`，原生必须先保存 `save` 再 pop；旧网页不带 `save` 的 close 不覆盖旧存档。
- 原生备用返回按钮可读取 `window.brainPlayExportSave()`，然后按相同顺序保存和 pop。加载失败且没有此函数时直接返回，保留旧存档。
- 原生仅校验来源、主 frame、合法 JSON 和 8 MiB 大小限制，写入使用原子替换。未带 `save` 不覆盖旧文件；显式 `save: null` 则保存 JSON null。网页改数据结构时，先识别、迁移旧存档，再在原有返回时机提交；App 不参与迁移。
- 无逐步传输、定时器、后台／关闭事件抢救保存，也不做账号或云端同步。

## App 页面与关卡通知 v1

所有游戏在进入、选关、下一关、重新开始／新一局，以及刷新网页后，通过同一 `brainPlay` 接口发送 `type: 'navigation'`。返回小游戏首页也发送通知。是否展示插屏由 App 决定。支持放行回执的 App 内，网页照常加载资源和画面，只暂缓游戏操作；不需要广告立即可玩，需要广告则关闭后恢复操作。

```js
window.webkit.messageHandlers.brainPlay.postMessage({
  type: 'navigation', source: 'brain-play', version: 1,
  navigation: {
    id: 'document-uuid:7', screen: 'game', game: 'g010',
    level: '7', reason: 'select', daily: false
  }
});
```

- `id`：每次页面加载生成随机文档标识，加递增序号。原生按 ID 去重；刷新文档会使用新标识。
- `game`：使用上表固定编码。`level` 为从 `1` 开始的字符串；无编号的随机游戏为 `round`，机关自由实验为 `sandbox`。2048 的 `variant` 为 `classic:4`、`fibonacci:5` 等；每日挑战另带 `daily: true` 和 `day: 'YYYYMMDD'`。
- `reason`：`enter` 进入、`reload` 网页刷新、`select` 选关、`next` 下一关、`restart` 重试本关、`new-round` 新一局、`settings` 切换棋盘／玩法；预留 `previous`。返回首页为 `{id, screen: 'home', reason: 'back'}`，首次打开首页用 `enter`／`reload`。
- 每次确认完成的关卡切换只发一次。取消重开、普通移动、撤销、提示、开关帮助，以及未改变游戏设置均不发送。
- 导航消息不携带存档、不写手机文件。返回首页先发送 `save` 再发送导航；返回 App 仍发送带存档的 `close`，原生保存成功后 pop，并按原生页面返回处理广告机会。
- 当前 iOS 接入共用 `GoAIAdsManager`：去广告权益、同意状态、前台、广告就绪和全局 300 秒冷却统一判断；连续快速切页合并到最后一次，页面离开或加载失败不展示。旧 App 忽略未知消息，普通浏览器不发送。

原生支持此流程时，在 `documentStart` 注入 `window.__brainPlayHost = {version: 1, navigationGate: true}`。收到导航后，不展示广告立即发送回执；实际展示时在 SDK 关闭或展示失败后发送：

```js
window.dispatchEvent(new CustomEvent('brainPlayResume', {
  detail: {id: '与 navigation.id 相同的值'}
}));
```

网页只接受当前等待 ID 的回执。进入页面时资源与棋盘正常加载，等待期间屏蔽游戏触摸和键盘；重开、换关的状态更新在放行后执行。离开页面取消旧等待，迟到回执不影响新游戏。无回执能力的旧 App、普通浏览器及失效接口保持直接可玩，不等待不存在的回执。原生不可只声明 `navigationGate` 而不实现每次导航的回执。

本地 `dev/app-navigation.html?app=1&lang=zh-CN#/` 可查看真实游戏发出的消息；它使用独立内存存档，不覆盖试玩进度，也不显示广告。可关闭“App 自动放行”，查看加载后的棋盘被暂时锁定，再点“App 放行”验证恢复操作。

真机测试可用 `node dev/native-fixture.mjs /tmp/brain-play-navigation-device-site.html` 将当前代码、样式和全部模块打包为独立 HTML。原生 XCTest 将此文件载入真实 WKWebView，以免把尚未发布的网页当成线上版本测试；测试完成后删除手机中的专用缓存快照，正式 App 不使用这个入口。


## 设计与边界

单机游戏，提供简体中文、繁體中文与 English，键盘焦点、减少动画偏好与手机布局。首页只有游戏宫格和设置，规则收在游戏页面的帮助按钮中。语言、音效和动画只在首页设置中出现；游戏内齿轮只显示当前游戏支持的专属设置。不做联网排行榜或账号同步。
代码、图案和界面为本项目编写；没有引入第三方游戏代码和商业游戏资源。


## 手机交互验证（2026-10-20）

每个游戏都检查了触摸、撤销／重开、页面切换和多语言，新增移动轨迹及连续输入保护。`motion.js` 管理可取消动画，关闭动画或系统减少动态效果时直接呈现结果；切换游戏会取消残留动画和重开确认框。

## 蚂蚁多米诺

玩法参考 [Domino-Chain](https://domino-chain.gitlab.io/)。参考项目为 C++／SDL、GNU GPL 项目；本仓库中的引擎、图形、音效与关卡为独立编写，没有复制它的源程序、资源或原版 Push-Over 数据。当前版本是 36 关的手机改编，支持以上六种骨牌；没有实现原作的全部骨牌、关卡或文件格式。原项目规模核查和本地难度设计见 [DOMINO_RESEARCH.md](DOMINO_RESEARCH.md)。

`domino-engine.js` 处理平台寻路、搬放约束和离散事件连锁，画面只播放事件轨迹，不参与胜负判定。相同时间的事件统一处理，开门牌与其他牌同时倒下不能开门。搭桥牌填补一格断口；落下的牌需击中分叉牌才能续传，落到其他牌会撞坏。

`domino-scenery.js` 独立绘制五种原创 SVG 远景，每章固定一个场景与光照：入门 1–12 关为庭院，进阶 13–18 关为工坊，挑战 19–24 关为游船港湾，大师 25–30 关为傍晚的高楼城市，终局 31–36 关为古代遗迹。选关界面显示章节对应的场景名；场景不随单关编号切换。远景位于棋盘镜头外，拖动和缩放时保持完整；船身轻晃、云层缓慢移动，遵循首页动画开关与系统减少动态效果偏好。平台与梯子的颜色随场景协调，碰撞、通关规则和存档格式不受场景影响。

`domino-material.js` 为棋盘、携带牌与图鉴共用原创 SVG 立体材质，包含侧面厚度、顶面、倒角、高光、凹刻符号与落地阴影。`domino-resting.js` 根据相邻牌的可见姿态计算倒下后的搭靠角度及遮挡层次：先倒的牌搭在下一张上，末张平放；左右方向及分叉的两半分别处理。这些计算仅影响画面，不改变连锁时序、胜负或存档。

`domino-levels.js` 的每关都有实际可走的搬牌解法；测试执行每一步行走、搬起、放下和推动，并验证最终开门与出口可达。下一步提示根据当前摆法导向已验证的参考布局，保留已有操作，并标出要搬的牌、放置格与应点的按钮；不承诺最短搬运路径。失败后的“回到摆放”保留本次尝试前的安排；连锁播放中离开／刷新会恢复已计算完成的尝试结果，不保存半截动画。

失败原因常驻棋盘正下方：开门牌提前倒下或与其他牌同时倒下时，统一提示“开门牌必须最后一个倒”；仍有牌站立或撞坏时分别说明，并标记相关骨牌。“机关”与“出口”在画面中分别标注，开门后有信号线显示远程控制关系。

## 机关工坊：正式关卡

## App 暂停与恢复接口 v1

App 用一个完整状态快照通知网页前后台和广告状态；插屏、奖励广告共用此接口，关闭和展示失败都会更新。它只管理游戏运行，不阻止 HTML、模块、图片等资源继续加载。

```js
// documentStart：保留 navigationGate，并加入初始 activity。
window.__brainPlayHost = {
  version: 1, navigationGate: true,
  activity: {version: 1, active: true, ad: false}
};
// 运行中：App 派发同一个事件，两个布尔字段每次都必须提供。
window.dispatchEvent(new CustomEvent('brainPlayActivity', {
  detail: {version: 1, active: true, ad: true}
}));
```

- `active`：App 可交互时为 true，失去活动状态、锁屏或切后台为 false。
- `ad`：原生全屏广告开始展示前为 true，SDK 确认关闭或展示失败后为 false；横幅不改变此值。
- 仅当 App 活动、没有全屏广告、网页可见且关卡导航已放行，游戏才能继续。重复通知无副作用；广告关闭但 App 仍在后台时继续暂停。
- 网页已加载后仍会在 ready 握手中接收当前状态，刷新则从最新 documentStart 快照开始，避免漏掉加载期间的通知。旧 App 使用网页可见性作为后备，普通浏览器只使用网页可见性。
- 所有游戏的共享音效、CSS／Web Animations 动画统一接入。骨牌行走与连锁等待保留剩余时间；机关模拟与绘图暂停且恢复时不补算后台时间。用户手动暂停仍由游戏自身保持。短音效被打断后丢弃，不在回来时补播。
- 此接口不写入原生存档，不触发广告，也不改变返回时先保存再退出的规则。导航放行回执 `brainPlayResume` 保持原有用途。
- 本地 `dev/app-navigation.html` 的“App 在前台”和“广告显示中”复选框发送相同真实接口，使用独立内存存档。


## App 初始化配置与能力 v1

沿用 documentStart 的 `__brainPlayHost`，新增 App 信息、能力与默认设置，旧的 navigationGate/activity 字段仍可使用：

```js
window.__brainPlayHost = {
  version: 1,
  app: {platform: 'ios', version: '1.0', build: '1'},
  capabilities: {
    navigation: true, navigationGate: true, activity: true,
    save: true, close: true, result: true
  },
  config: {language: 'zh-CN', sound: true, animations: true, theme: 'light'},
  navigationGate: true,
  activity: {version: 1, active: true, ad: false}
};
```

网页 ready 附带 `client: {build:'27', protocol:1, capabilities:[...]}`，App 可识别网页版本及支持的接口。能力明确为 false 时，网页跳过不支持的请求；没有结果能力的旧 App 不接收结果消息，旧导航放行字段仍兼容。普通浏览器不发送 App 消息。当前主题支持 light。

语言优先级为显式链接 lang、网页已保存的选择、App 默认语言、浏览器语言；音效和动画优先采用网页存档，未设置时采用 App 默认值。iOS 正常入口移除了写死的 lang，默认读取 App 所选语言、声音偏好及减少动态效果设置。网页配置不会修改 App 的全局设置。

## 本局结果 v1

游戏发生结算时，通过同一个 brainPlay.postMessage 发送：

```js
{
  type: 'result', source: 'brain-play', version: 1,
  result: {
    id: 'round_example_001', game: 'g001', level: 'round',
    variant: 'classic:4', daily: false,
    outcome: 'won', activeMs: 42350, score: 2048
  }
}
```

- id 在本局中保持不变，返回、恢复时随局面继续；重开、新一局、换关生成新编号。App 按编号去重，重复发送／重新打开 App 不重复记入结果。
- game 使用 g001～g011；编号关卡从 1 开始，随机局使用 round，自由实验不产生胜负结果。variant、daily/day 与关卡描述一致。
- outcome 为 won／lost／finished。2048 首次达标记 won，继续挑战不再次结算；未达标且无合法移动记 lost。消灭星星无可消除时记 finished。24 点未算到 24 仍可撤销，不误记失败。骨牌在失败连锁结束或真正进门后结算；机关挑战在成功或运行失败后结算。
- activeMs 为本局活动毫秒数，包含思考、摆放和游戏动画，扣除广告、后台、网页隐藏以及机关的手动暂停。续局累加，结算后固定。
- 只发送游戏有可靠来源的指标：score、moves、attempts、assisted；没有累计数据时省略，不用有上限的撤销历史推算总步数。
- 每局最多发送一次结果，撤销后重做不会重复；恢复老存档不会补发历史成绩。普通操作仍只更新网页内存／浏览器存储，不把局面每步传给 App。
- 原生仅接收本站主 frame 的有效消息；结果写入 App 私有 BrainPlay/round-results-v1.json，保留最近 1000 局，独立于返回时保存的局面文件。重复编号不再写入，损坏历史文件保留并报告内部 resultError。结果不会触发广告、跳转页面或覆盖游戏存档。
- 局面中的保留字段 __round 只保存编号、活动时长、是否已结算；游戏仍按原有规则恢复。
